    Quick start

    Your first message in under five minutes.

    1. Create a key

      Sign up and copy a sandbox key. It starts with rm_test_ and sends only to addresses you have verified.

    2. Verify your domain

      Add three DNS records (SPF, DKIM and a return path). Most providers pick them up in under ten minutes.

    3. Send

      Install the SDK for your stack and call messages.send. To go live, swap in a rm_live_ key.

    send.ts
    import { Relaymark } from "@relaymark/node";

const rm = new Relaymark(process.env.RELAYMARK_KEY);

await rm.messages.send({
  from: "Acme Receipts <receipts@example.com>",
  to: "dana@example.com",
  subject: "Your receipt #2041",
  template: "receipt",
  data: { total: "$48.00" },
  fallback: { sms: "+15550100199", after: "15m" },
}, { idempotencyKey: "order_2041" });
    send.py

    Message lifecycle

    Know where every message is, to the second.

    Each message moves through five states, and each move fires a signed webhook. You never have to poll, and you can always answer a support ticket that starts with “I never got the code.”

    message.queued+0 ms

    Accepted

    We validate the request, store it, and return an ID before we contact any mailbox provider.

    message.sent+380 ms

    Handed off

    Sent from a warmed IP pool, matched to your domain’s reputation and the recipient’s provider.

    message.delivered+2.1 s

    Accepted by inbox

    The receiving server confirms delivery. For SMS, this is the carrier’s delivery receipt.

    message.openedlater

    Engaged

    Opens and link clicks, if you turn tracking on. It is off by default for auth codes.

    message.failedany time

    Bounced or blocked

    Returns a plain-English reason and a code. We suppress the address automatically.

    Signed webhooks with automatic retries

    Every payload is signed with HMAC-SHA256. If your endpoint fails, we retry with exponential backoff for up to 72 hours.

    rm.webhooks.verify(body, headers["rm-signature"])

    Idempotent by design

    If you send the same request twice with the same key, we send one message. Retries after a network timeout are safe for 24 hours.

    Idempotency-Key: order_2041

    Email first, SMS as backup

    If a one-time code isn’t delivered or opened in time, we resend it by text automatically. It is one message ID on one bill.

    fallback: { sms: "+1…", after: "15m" }

    Security & compliance

    The questionnaire answers, already written.

    Your security team will ask, so here are the answers. Reports, our DPA and the subprocessor list are in the Trust Center, and you don’t need an NDA to read the summaries.

    SOC 2 Type II & GDPR

    Audited every year by an independent firm. The DPA is signed when you click a button, and we publish 30 days’ notice of any subprocessor change.

    EU data residency

    Pin message bodies, logs and backups to eu-central. Data never leaves the region, not even for support.

    Scoped, rotating keys

    Limit a key to one domain, one channel or read-only logs. You can rotate keys without downtime and restrict them to your own IP ranges.

    Redaction on by default

    We detect one-time codes and reset links and mask them in logs after delivery. Your support team sees the status, not the secret.
